## 升级前必须知道

1. **会话与数据库**：本轮已合并改动将 SQLite 升级到 schema 21、Redis 到 13，旧浏览器会话失效，需要重新登录。密码、API key、文件和公开分享不会因此自动轮换或删除。停掉旧实例并备份配置/数据库；不能用旧程序直接读写升级后的会话库。回退必须按[会话升级说明](../security/session-lineage-logout.md)恢复兼容的升级前数据库备份，并在对外提供服务前撤销恢复的旧会话。
2. **OIDC 身份迁移**：既有 OIDC 账号（包括初始管理员）不能依靠 email 自动关联。先在可信 IdP 侧核实 issuer/subject，按[身份迁移说明](../security/OIDC-IDENTITY-MIGRATION.md)显式绑定，再开放登录。不要为了恢复登录而关闭身份核验。
3. **OIDC 部署条件**：非 loopback URL 要求 HTTPS；IdP 必须支持 S256 PKCE 与 ID token nonce。未完成登录的事务为进程内、10 分钟、最多 4096 条；重启或回调到另一进程会安全失败并需要重新登录。不是共享多实例事务服务，见[state 说明](../security/OIDC-STATE-TRANSACTIONS.md)。
4. **退出集成**：旧 GET `/logout` 调用需迁移为 `/logoutToken` 后的 POST；内置 UI 已更新。强制改密用户仍可退出，退出不会解除改密要求。
5. **CLI 与密钥**：旧 CLI 凭据不自动迁移，建议按[凭据说明](../security/CLI-CREDENTIAL-STORAGE.md)重新登录。已泄漏密钥仍需单独撤销；本次不会自动轮换。目录上传不再接受符号链接；API key 已超限的旧记录仍可管理，新建受[容量限制](../security/api-key-capacity.md)。

## Upgrade notes (English)

1. **Sessions and database rollback.** PR #97 upgrades SQLite to schema 21 and Redis to schema 13 and invalidates existing sessions. Users must sign in again. Stop the old instance and back up configuration and database before upgrading. An older binary cannot safely read or write the upgraded session store. To roll back, restore a compatible pre-upgrade database and revoke all restored sessions before serving traffic. Follow the [session migration and rollback procedure](../security/session-lineage-logout.md).
2. **Existing OIDC identities.** Verify each existing account's exact issuer and subject with the trusted IdP, including the initial administrator, then perform the explicit binding described in the [identity migration procedure](../security/OIDC-IDENTITY-MIGRATION.md). Matching email addresses alone cannot associate an existing account.
3. **OIDC deployment requirements.** PR #98 requires HTTPS for every non-loopback public URL. The IdP must support S256 PKCE and return the transaction nonce in the signed ID token. Pending login transactions live in process memory for ten minutes, with a maximum of 4096 entries. Each callback must reach the same process that started its login. A process restart or routing to another node requires a new login attempt. See the [OIDC state transaction requirements](../security/OIDC-STATE-TRANSACTIONS.md).
4. **Logout integrations.** Obtain a fresh browser-bound token from `/logoutToken`, then POST it to `/logout`. The built-in UI implements this flow. Users awaiting a mandatory password change can still log out, and the password-change requirement persists.
5. **CLI credentials and keys.** Reauthenticate the CLI using its [private credential location](../security/CLI-CREDENTIAL-STORAGE.md). Exposed keys require explicit revocation. Directory archives reject detected symbolic links and special files. Existing keys above the new creation limits remain manageable under the [API key capacity policy](../security/api-key-capacity.md).
