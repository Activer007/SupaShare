# File Request 数量、分页与生命周期（N13）

## 使用规则

- 新收集默认有效 5 天；普通账户新建或变更截止时间时最长 90 天，不能新建永久邀请。API 传入零会采用默认期限。网页新建表单始终要求有限期限。
- 老请求的期限不因修改名称或说明而改变，包括历史永久请求。管理员通过 API 仍可使用永久或更长期限。
- 每位所有者最多保留 100 条请求，全局最多 10000 条；关联邀请凭证也受相应上限保护。请求和邀请凭证原子创建，配额失败不留下独立凭证。
- 到期后邀请凭证不可继续用于上传。空请求在到期保留期 7 天后可由有界清理删除元数据；仍有文件的请求保留用于管理，并继续占用请求名额。清理不能自动删除已上传文件，也不能回收正在提交的上传资源。
- 不要为了腾出请求名额盲目点“删除”：**原有手动删除操作会删除关联文件**。先确认业务保留要求。
- 本次不迁移历史永久请求为有限期限，不自动删除用户文件。

## 分页与刷新

`GET /api/uploadrequest/list?limit=50&before=<cursor>` 保留 JSON 数组响应，默认 50 条、最多 100 条。按创建时间和 ID 从新到旧排序，响应头 `X-Next-Cursor` 提供下一页游标。不要自行构造或解析游标。

网页提供“最新收集”和“下一页”，数量仅指当前页。具备跨用户查看权限的账户仍可以看到获授权的其他用户记录。当前页刷新逐条核对已渲染请求，最多同时发起 4 个读取，不把第一页结果当成全量快照。新建请求在刷新期间出现时，不会因缺席旧快照被误判为无权访问。

列表不是跨请求的事务快照。巡查期间出现的新记录可回到“最新收集”查看；不要依赖列表分页实现严格一致的导出。

## 错误与重试

- `400`：无效游标、分页参数、截止时间或输入；调整参数。
- `409`：请求被并发修改或邀请已到期；刷新后核对，不覆盖旧快照。
- `429`：请求或附属凭证名额已满；检查已保留记录，勿自动重试创建。
- `503` 或创建响应丢失：结果可能未知，先检查列表是否已经创建，再决定重试。本接口未承诺创建幂等性。

## 升级及边界

SQLite 升级到 schema 24，Redis 升级到 schema 16 并一次性建立请求、关联文件和邀请凭证索引。升级前备份数据库，停止旧版本写入，不要让新旧版本同时操作同一数据库。历史超过配额的数据保留，但在降到上限以下前不能继续创建；历史孤立邀请凭证也计入配额并由有界维护清理。
