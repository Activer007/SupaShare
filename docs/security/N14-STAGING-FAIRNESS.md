# N14：按用户与 File Request 限制暂存字节占用

基线：`d6d481fec8b61c40a7f760c299d8943efe4667ba`（PR #111 已合并）。
对应新 CSV 第 18 项 `acf_36866b2aad68140ce352846f8e677e36`。

## 本组范围

E 组已经缩短无进展预约的有效期，并增加接收正文的进展预算。本组补齐另一层：普通账号归属的公开链接持有人发送一片有效数据后，不能仅凭一个 File Request 或一个普通 owner 声明的总文件大小占满整个实例的暂存预算。管理员豁免的例外见下文。

沿用同一 SQLite 事务 / Redis CAS 账本，不增加表或后台系统。Reserve、首次 Bind 在原子容量检查中同时核对全局、owner、request 的未释放暂存字节。整文件和分片共用该检查，普通账号的整文件没有 request 层，但仍受 owner 层限制。创建多个公开链接不能绕过同 owner 的聚合上限。

保守峰值声明不变：整文件 `4 × 文件大小 + 64 KiB`，分片 `4 × 文件大小 + 1 MiB`。本组不改为仅按已接收字节计费，因为拼装、加密等后续阶段仍需要峰值空间。

## 配置与行为变化

| 配置 | 默认 | 语义 |
| --- | --- | --- |
| `GOKAPI_UPLOAD_STAGING_MB` | 12288 | 实例硬上限，沿用原配置 |
| `GOKAPI_UPLOAD_USER_STAGING_MB` | 0 | 0 自动取全局的一半；正数为 owner 上限 |
| `GOKAPI_UPLOAD_REQUEST_STAGING_MB` | 0 | 0 自动取全局的四分之一与 owner 上限的较小值；正数为单 request 上限 |

单位均为 MiB，0 在新增配置中只表示自动派生，不是无限。拒绝负数、非整数、溢出值、owner 超过全局、request 超过有效 owner 的配置。提高份额不提高全局硬上限，也不取消接收槽、逻辑配额、文件大小或活动数量限制。默认份额对普通账号归属的整文件上传和公开上传一致生效；管理员明确配置接近全局的份额会减少其他主体的保留空间。

**默认 12 GiB 全局预算下，owner 为 6 GiB，request 为 3 GiB。** 普通账号的新公开分片上传的单文件容量最多约 768 MiB，准确上限为 `(3 GiB - 1 MiB) / 4`，且还要扣除同 request 已占用额度。普通整文件为 `(6 GiB - 64 KiB) / 4`。这不是文件大小设置的替代，而是额外资源限制，升级时务必检查合法大文件场景。

例如保留全局 12288 MiB，同时允许单 request 上传 2 GiB 分片文件，可显式设置 owner/request 各 9000 MiB。2 GiB 文件的声明为 8193 MiB，仍需满足其他限制。不要设置为 8192 MiB 后期待恰好支持 2 GiB：附加开销仍需计入。可选的大文件回归夹具使用这一明确配置，不声称本次实际执行了 2 GiB 压测。

## 管理员豁免与展示

按用户指示，Admin / Super Admin 不受累计字节总额度限制，包括 owner / request / instance 的逻辑累计字节额度，也不受新增 owner/request 暂存份额限制。普通账号仍受这些业务字节额度限制，管理员占用仍计入账本总量。普通账号的实例逻辑总量判断仍包含管理员文件，因此管理员大量存储可能使普通账号触及实例逻辑上限；本组不新增隔离存储池。

**不是全部限制都关闭。** `GOKAPI_UPLOAD_STAGING_MB` 是所有账号共同遵守的物理暂存硬上限；最小可用磁盘、正文接收预算、文件数量与并发数量也保留。每个文件的大小限制、File Request MaxSize 和既有单文件校验完全不改。实例累计逻辑字节上限与物理暂存上限是不同概念，不能混称。

SQLite 在配额事务内读取当前 owner 角色；Redis 在 WATCH owner 用户 hash 后读取角色，角色变化将使事务重试。拒绝信任请求传入的管理员标记。缺失用户不会因零值 rank 被当作 Super Admin。公开 File Request 按归属 owner 的当前角色执行，而非匿名链接持有人、创建请求的操作者或当前查看页面的人。

**管理员公开链接风险：** 管理员名下公开 File Request 的匿名持有人同样继承归属 owner 的额度豁免，仍可声明接近全局暂存硬上限的文件，竞争或挤占实例预算。E 组的租约、进展和接收预算仍有效，但不能把本组结论写成所有公开链接都有公平份额隔离。此行为保留用户明确要求的管理员总额度豁免，不擅自按匿名访问身份取消豁免；建议管理员谨慎传播公开链接，需要份额隔离时使用普通业务账号持有链接。

升为管理员后下一次操作使用豁免；降级后新 Reserve/首次 Bind 回到普通限制。已绑定上传仅按以下祖父规则保留非增长完成能力。权限豁免不取消 File Request 到期、撤销或身份验证。转交按接收 owner 判断，复制按新副本 owner 判断，替换按目标文件 owner 判断，使用同一 provider 有效额度。

管理员面板只读展示普通账号的限额及当前配置，并明确管理员不受累计业务字节额度限制，避免把管理员当前用量绘成普通用户配额的耗尽进度。

## 旧上传、配置下调和清理

不改账本 schema，也不批量改写旧记录。升级前已绑定的未释放记录，同一 ID、同 owner/request、暂存声明不增长时，允许重试、Progress、Claim、Commit 继续原流程，即使超过新份额。它们仍必须通过既有全局、逻辑容量、权限和有效期检查。

祖父兼容只适用于已绑定的现有占用，不适用于首次 Bind、换 ID、换 owner/request、增大声明或已经释放的回执。旧超额记录仍全额计入后续准入，因此配置下调后可能暂时没有新上传名额，直至旧上传完成或确认清理。

Reserved、Uploading、Committed 等所有尚未确认释放的记录都占用暂存额度；到期或逻辑状态变化不能凭空退额。清理失败继续保额；Abort/ReleaseStaging 确认释放后才恢复份额。候选记录从累计中排除后只计一次，全局溢出检查也约束子项加法。

## 验证与剩余边界

账本测试覆盖分层累计、不同 owner 保留空间、多 request 不能绕过 owner、终态未释放、旧记录重试、不允许新绑定借用祖父例外、配置下调、失败清理和溢出。配置测试覆盖自动值、管理员覆盖和非法输入。Provider 并发回归单独验证 SQLite / miniredis 的原子准入。

同一 bearer 链接的多个持有人仍无法区分；本组提供 owner/request 隔离，不保证同一链接内部公平。多个恶意账户仍可共同竞争全局份额，边缘限速和账户治理仍由部署者承担。物理磁盘可用空间、HTTP 接收副本、账本数量与这些份额是不同限制，不把暂存预算称为完整磁盘防耗尽方案。

交付测试记录以实际运行结果为准；真实 Redis、浏览器和大文件速率测试未执行的部分不以 miniredis 或单元测试替代。
