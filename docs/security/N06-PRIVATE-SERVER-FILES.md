## 修改范围

提取既有 CLI credential 文件实现为 `internal/privatefile`，由 CLI、主配置、云存储配置和 setup 证明共同使用。不是新增另一个密码库，也不修改认证协议、数据库账户或单文件上传策略。

1. 读之前验证真实父目录及祖先、最终文件类型、所有权和平台保护；拒绝 symlink、设备、目录和不安全文件。打开后校验 inode/文件身份一致。
2. 写之前把 JSON/YAML 完整编码到内存，不再直接打开最终路径并 `O_TRUNC`。在固定父目录内用随机独占名称创建临时文件，先建立并验证保护，再写秘密字节，sync、close，最后 rename 替换目录项。
3. 已存在的、自有但权限宽松的普通文件可在写入时安全替换为新 inode，不直接 chmod/truncate 老 inode；因此旧硬链接内容不会被新秘密覆盖。读取旧宽松文件仍拒绝，不能先读取再补权限。
4. Unix 替换后同步父目录。Windows 校验受保护的 DACL 与实际 ACL，写入前复验；目录持久性与替换行为仍依赖平台，不将交叉编译当作原生验证。
5. setup 先清空旧内存证明，只有私有证明文件创建、保护、写入和同步成功后，才把新口令设为有效。失败不激活证明，不打印口令；正常结束删除文件。
6. 配置存在性检查不会把 dangling symlink 误认为未安装。云配置的安全验证/读取失败终止加载，不悄悄退回本地存储；不存在云文件仍保留原有可选语义。格式错误 YAML 的原有报错语义不在本组扩展。
7. 共享原语的删除只接受经过父目录/最终类型检查的普通文件，不跟随链接。缺失文件是可接受的清理结果。

## 升级与部署注意

本组故意 **fail closed**。旧安装的配置文件若对其他账号可读，或父目录允许其他账号写入，将拒绝启动/配置读取，而不是静默修复目录或放宽检查。部署前由管理员检查：

- 主配置及 `cloudconfig.yml` 归运行服务的账号所有，Unix 权限通常应为 `0600`；目录建议 `0700`，至少不能被其他账号写入。
- 祖先可以是可信系统目录；共享可写直接父目录不可用。允许祖先的 sticky `/tmp`，但不能直接把 `/tmp` 作为秘密文件父目录。
- 不递归 chmod/chown 共享路径，也不自动修改已存在目录的 ACL。把文件迁入专用真实目录，确认所有者及 ACL 后再启动。
- macOS 的 `/var`、`/tmp` 常为系统链接；目前沿用严格祖先链接拒绝策略，应配置真实路径（例如由管理员确认后的 `/private/...`），不要以忽略错误代替保护。继承的 Darwin ACL 若授予额外访问将拒绝，不自动剥离 ACL。
- Windows 需验证运行账号、父目录 ACL、受保护文件 DACL及已有目标替换；UNC/reparse/junction 或无法验证的保护应拒绝。仅交叉编译不证明原生运行行为。
- 新建配置目录使用 `0700`，但这不等于已有目录已被修复。`-c` 主配置路径和环境 ConfigDir 可能不同，分别验证各自父目录。
- 替换不会撤销此前已通过宽松文件或旧硬链接泄露的凭证；若曾暴露，应另行轮换相关 OAuth、存储和数据库秘密。

文件 sync 成功但 rename 后的目录 sync 失败时，返回错误，但新文件可能已经发布。不要按“报错等于未修改”盲目重复流程，应检查实际受保护文件状态。权限错误不记录秘密内容。

## 验证边界

Linux 回归包含：共享原语及 CLI，主配置宽松权限拒读、安全替换不改旧硬链接、最终链接不跟随、可写父目录拒绝、dangling link 不进入首次 setup、云配置不安全读取不降级、setup 失败不激活旧证明；原有平台专项测试随原语迁移。

Windows amd64 / Darwin arm64 的 privatefile 与 CLI 测试包可交叉编译；**尚无本次原生 Windows ACL/rename 或 macOS ACL 运行证据**。后续 Mac Codex 应运行 Darwin 专项测试；Windows 必须另保留原生验证待办，不把编译通过标为两项跨平台风险全面验收完成。

这不是对数据库文件、日志、TLS 私钥、所有用户上传文件或整个 ConfigDir 的全面权限重构；本批不推进 N07。
