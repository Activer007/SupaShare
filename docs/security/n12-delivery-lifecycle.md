## 最小策略

- 新建 Delivery：每所有者最多 100 条，全站最多 10,000 条；管理员不豁免数量。已撤销／过期但尚未清理的记录也计数，阻止 create/revoke 持续积累。
- 普通账号新建时不填期限默认 30 天，最大 90 天；管理员允许显式永久（expiresAt=0）。数据库准入为单 SQL / Lua 原子配额，不依赖单进程 mutex。到期规则仍由业务服务校验。
- 过期或撤销后保留七天，再清理 Delivery 元数据。两个事件都有时以较早事件为准；不会删除源文件、blob 或改变下载次数。创建前清理至多100条，已有定时维护每小时至多1000条，有5秒上下文预算。
- 旧永久列表不静默改期；旧数据超配额时仍能分页管理／撤销，但不能新建，直到存量下降。离线数据库迁移仍使用保留全部记录的 InsertDelivery，不应在在线路由调用它。
- `/api/deliveries/list` 保持数组响应，但默认50条，`limit` 为1–100；`before` 为上一页 `X-Next-Cursor`。按创建时间、Token降序稳定keyset排列，用户身份始终来自认证，不接受owner参数。游标可在原记录删除后继续；它不授予查看别人的权限。
- 管理页面提供“加载更多”。创建结果未知时只有完整遍历刷新后的所有页才解除重试保护；列表查询不重复创建。它不是跨请求数据库快照，其他标签并发新建时应再次刷新核对。

## 升级与限制

停止旧服务实例、备份数据库后统一部署。Redis首次启动通过旧记录哈希建立owner/清理索引，只有完整成功才写完成标记，可重试；老实例不维护索引，因此不能新旧混跑。索引构建为启动迁移而非请求时全局扫描。SQLite新增owner/token和到期／撤销索引。离线导入也维护Redis索引。

有界清理不会一次扫完超大历史积压，配额拒绝可能持续到后续批次。到期撤销后七天会不可逆地移除列表标题、备注、成员关系和管理链接；如需历史审计请在升级前备份，源文件不受此清理影响。Redis持久化依赖部署配置，本补丁不配置备份或故障转移。

验证结果由本次交付报告记录。miniredis并发测试不等同真实Redis、故障恢复或生产容量验证；浏览器真实点击仍需本地Codex验证。没有部署生产或更改现有数据。
